# JapanEx release readiness

Last checked: 2026-09-25. This records evidence for the current worktree; it is not a store approval.

## Verified

- `bun run verify`: data validation, 39 tests, TypeScript, and Expo lint passed.
- `bun run export:web`: static web export passed.
- The Play icon is a 512 × 512 RGBA PNG under 1 MB. The three localized feature graphics are opaque RGB PNGs at 1024 × 500. Draft phone screenshots are opaque 1080 × 1920 PNGs, and the existing tablet sets contain four opaque PNGs each; the tablet 5:8 ratio differs from Google's current 9:16 large-screen guidance and should be revisited during final capture.
- Expo config introspection for the current worktree generated an Android HTTPS `/view` intent filter with `autoVerify`, removal directives for overlay and media/storage permissions, and an iOS Associated Domains entitlement for `japanex.expo.app`. This checks config-plugin output; the final signed artifacts still need inspection because native dependency manifests and signing are resolved during builds.
- The new support page is present in the web export at `dist/support/index.html`; the exported support and privacy HTML match their source files byte for byte. On 2026-09-25, the live support and privacy URLs both returned HTTP 200 with HTML content types and matched the current source files byte for byte. The `/view` route returned HTTP 200. Both public `.well-known` association files returned HTTP 200 with JSON content types and matched the current source files byte for byte.
- Fresh iOS Release simulator builds succeeded with `xcodebuild` for the JapanEx scheme after the UI and export edits. They include an embedded `main.jsbundle`; the app reports bundle ID `dev.expo.kudo.japanex` and version `1.0.0`.
- The Release build installed and launched in isolated iPhone 17 Pro Max and 13-inch iPad simulators. Captured Map screenshots have the expected 1320 × 2868 and 2064 × 2752 dimensions. The map, score, labels, zoom controls, navigation, and legend fit on iPad. On iPhone, the floating tab bar overlays lower content at the initial scroll position; a Maestro scroll reached the legend and Share result image control.

The Flags count showed 47, its search field and filter controls were visible, and Settings showed the updated score and backup copy. Map Zoom in visibly enlarged the map and Reset view returned it to the original bounds. The map score, Settings summary, and Flags filters now stack at that size, and level text can wrap. New Release screenshots of Map, Flags, and Settings showed separated values and controls. Native export waits for SVG layout, writes iOS's line-broken base64 using Expo FileSystem, and normalizes native raster output with Expo ImageManipulator. ## Still required before submission

- Run the final signed iOS and Android builds. The local iOS simulator build does not verify signing or App Store packaging. This host has no Android SDK, so the merged release manifest and AAB still need inspection from a new Android build. Existing EAS artifacts are older than this worktree.
- Verify offline launch on native devices or simulators and screen-reader navigation at large text sizes on physical devices. [Apple's accessibility test guidance](https://developer.apple.com/documentation/accessibility/performing-accessibility-testing-for-your-app) says VoiceOver is unavailable in Simulator. In Maestro, tapping a map SVG element by its accessibility label found the element but did not open the sheet; a physical tap on the visible shape did. The bundled `react-native-svg` iOS group hit test checks path bounds and delegates to child paths, so a coordinate tap at the accessibility element's center may miss an irregular region. A physical-device VoiceOver activation check is still needed; the Maestro result alone does not establish a screen-reader defect. Repeat view-only and confirmed-import links on Android; verify signed HTTPS links on both platforms.
- Export result images with flags on and off on Android. Inspect its actual PNG dimensions (required: 2048 × 2048), artwork bounds, and share-sheet cancellation behavior.
